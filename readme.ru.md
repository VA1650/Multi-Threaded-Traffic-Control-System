# 🚦 Multi-Threaded Traffic Control System

Высокопроизводительный симулятор дорожного перекрестка, написанный на Java, использующий продвинутые примитивы конкурентности для моделирования реальных правил дорожного движения и безопасности пешеходов.

---

## 🚦 Обзор

Этот проект имитирует сложный 4-сторонний перекресток с несколькими полосами движения, динамическими фазами светофора и пешеходными переходами. Он решает классическую задачу «производитель-потребитель», где полосы движения порождают «потоки автомобилей», которые должны безопасно преодолеть общий ресурс (перекресток) без дедлоков и столкновений.

## 🛠 Технологический стек

* **Язык:** Java 21+
* **Конкурентность:** `java.util.concurrent`
* **Синхронизация:** `ReentrantLock` (Fair Mode), `Condition` variables.
* **Исполнение:** `ExecutorService` (Fixed Thread Pool).

## 🧠 Основные функции многопоточности

### 1. Честное планирование (Fair Scheduling)
Все блокировки перекрестка и полос инициализируются с параметром `fair = true`. Это предотвращает **голодание потоков (Thread Starvation)**, гарантируя, что автомобили с оживленного направления не будут бесконечно блокировать транспорт с второстепенных дорог. Каждая машина получает свою очередь на основе времени прибытия.

### 2. Трехфазная логика светофора
Система реализует циклический автомат состояний:
* **Фаза 1:** Зеленый свет Север-Юг.
* **Фаза 2:** Зеленый свет Запад-Восток.
* **Фаза 3:** **Пешеходная фаза** (Все красные). Все потоки автомобилей приостанавливаются с помощью `Condition.await()`, пока пешеходы «переходят» перекресток.

### 3. Разрешение конфликтов (Уступка дороги)
Алгоритм `shouldYield()` реализует реальные ПДД:
* **Приоритет поворота:** Потоки автомобилей, совершающие левый поворот или разворот, автоматически проверяют реестр `carsInIntersection` и уступают дорогу встречному транспорту, движущемуся прямо или направо.
* **Очистка перекрестка:** При смене светофора новые потоки ждут, пока «старые» потоки из предыдущей фазы покинут перекресток, прежде чем въехать на него.

### 4. Потокобезопасный реестр
Система использует комбинацию `HashMap` (под защитой блокировок) и `CopyOnWriteArrayList` для управления состоянием активных транспортных средств, гарантируя, что проверки статуса никогда не вызовут `ConcurrentModificationException`.

## 🏗 Архитектура

* **`TrafficLightController`**: «Мозг» системы. Управляет блокировками, условиями и состоянием перекрестка.
* **`TrafficLane` (Runnable)**: Имитирует конкретную полосу (например, Север-Лево). Генерирует автомобили и управляет их жизненным циклом (**Ожидание -> Въезд -> Маневр -> Выезд**).
* **`TrafficLight` (Runnable)**: Фоновая служба, координирующая переключение фаз.
* **`PedestrianGroup` (Runnable)**: Высокоприоритетные сущности, которые инициируют условия ожидания для всех потоков автомобилей.

## 📈 Производительность и безопасность

* **Предотвращение дедлоков:** Строгая иерархия захвата блокировок (`laneLock` -> `lightLock`).
* **Оптимизация ресурсов:** Использование `Condition.signalAll()` для пробуждения только необходимых потоков, что снижает накладные расходы на переключение контекста процессора.
* **Безопасное завершение:** Все потоки корректно реагируют на сигнал `interrupt()`, обеспечивая чистое завершение симуляции.
